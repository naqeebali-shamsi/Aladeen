# Aladeen 0.7.0

## Learning update

- Review built-in lessons before writing managed guidance, with explainable approve/hold/reject decisions and a saved eligibility snapshot.
- Keep lessons from different projects separate. Require supporting sessions, providers and detector event references to match the destination project.
- Regenerate detector evidence from stored traces; source timestamps govern freshness.
- Measure recurrence within matching project/provider scope. Exclude duplicate/conflicting observations and unusable clocks; remove verified status when improvement is no longer supported.
- Preserve the original application boundary on unchanged refresh, retain negative evidence after withdrawal, and reconcile equivalent target paths.
- Refuse ambiguous fences and symlink/alias destinations, preserving text outside the managed block.
- Fix home-path boundaries and POSIX case handling. Claude project identity requires consistent actual transcript cwd metadata.

- Report the installed package version in the CLI instead of the old hard-coded value.

## Migration

Legacy lessons remain readable and are held from automatic guidance until scoped evidence is available. Rerun learning on usable traces; reingest older Claude or home-scrubbed traces as described in README.md. OpenClaw project identity remains unknown for automatic guidance. Project IDs describe a local working directory, not inferred repository equivalence.

## Release scope

This release is built from 0.6.0 with the reviewed learning update. The separate local daemon scheduler, engine refactor, demo and assistant skills are not included. Existing public learning parameter options and scrubber preserveOutput support are retained.

This is a diagnostic/learning update. It does not add general autonomous repair, authenticated source logs, semantic owner-rule conflict detection or inferred personal preference promotion. Recurrence measurements remain observational, not causal.


## Dependencies and verification

Compatible dependency updates and a tested migration to patched Zod 4 remove the production findings reported by npm audit. Sparse record schemas retain their existing optional-key behavior. Development-tool advisories are outside the installed production dependency tree and remain a maintenance follow-up.


Release validation: 527 tests across 45 files, typecheck, lint and build passed in the isolated release checkout. The original local checkout has additional unpublished scheduler/refactor tests. The npm archive excludes source tests, demos, local state and daemon modules.
